# 大语言模型原理

理解 LLM 的工作原理，才能真正用好它。本页从 NLP 的发展讲起，带你了解 Transformer、预训练、模型差异和能力边界。

## 从 NLP 到 LLM

自然语言处理（Natural Language Processing, NLP）是 AI 的一个分支，目标是让机器理解人类语言。它的演进可以分为几个阶段：

### 规则方法时代（1950s-1990s）

早期 NLP 完全依赖人工编写的语法规则。比如用语法规则解析句子结构、用词典做翻译。这种方法脆弱且难以扩展——每种语言、每个领域都需要单独编写规则。

### 统计方法时代（1990s-2010s）

研究者开始用概率模型从数据中学习语言规律。代表性方法包括 n-gram、隐马尔可夫模型（HMM）、条件随机场（CRF）。这些方法在词性标注、命名实体识别等任务上取得了不错的成绩，但特征工程需要大量人工设计。

### 深度学习时代（2013-2017）

Word2Vec（2013）的出现标志着词向量时代的开始。词语被表示为稠密向量，相似的词在向量空间中距离相近。随后 LSTM、GRU 等循环神经网络在序列任务上表现出色，但它们有两大瓶颈：

- 无法并行训练（必须按顺序处理每个词）
- 长距离依赖难以捕获（信息在长序列中逐渐衰减）

### Transformer 时代（2017-至今）

2017 年 Google 发表《Attention Is All You Need》，提出 Transformer 架构。它用自注意力机制替代了循环结构，解决了并行训练和长距离依赖两大问题，成为今天所有主流 LLM 的基础。

```text
发展脉络：
规则 → 统计 → 词向量 → RNN/LSTM → Transformer → GPT/BERT → 今天的大语言模型
```

## Transformer 架构核心思想

Transformer 的核心创新是**自注意力机制**（Self-Attention）。用通俗的话说：模型在处理每个词的时候，会回头看输入中的所有词，然后决定"哪些词对我当前的理解最重要"。

### 自注意力机制

假设你读这句话："小明把书放在桌子上，因为他觉得它太重了。"

当模型处理"它"这个词的时候，自注意力机制会让模型去关注所有其他词，然后发现"书"和"它"的关系最强——"它"指的就是"书"。

```text
处理 "它" 时的注意力分布：
  小明: 0.05
  把:   0.02
  书:   0.65  ← 注意力最高
  放:   0.03
  在:   0.01
  桌子: 0.08
  上:   0.02
  因为: 0.03
  他:   0.05
  觉得: 0.03
  太重: 0.03
```

这个过程是通过三个向量——**Query（查询）**、**Key（键）**、**Value（值）**——来实现的：

1. 每个词生成三个向量：Q、K、V
2. 用当前词的 Q 去和所有词的 K 做点积，得到注意力分数
3. 对分数做 Softmax 归一化
4. 用归一化的分数对 V 做加权求和

```text
Attention(Q, K, V) = Softmax(Q × K^T / √d_k) × V
```

::: tip 一个比喻
把自注意力想象成在图书馆找书。Query 是你的搜索词，Key 是每本书的标签，Value 是书的内容。你用搜索词去匹配所有标签，匹配度越高的书，对你最终的结果影响越大。
:::

### 多头注意力

单次注意力只能关注一种关系。多头注意力（Multi-Head Attention）让模型同时从多个角度关注输入：

```text
Head 1: 关注语法关系（主语-谓语）
Head 2: 关注语义关系（近义词、反义词）
Head 3: 关注位置关系（相邻词、远距离依赖）
Head 8: 关注指代关系（代词-名词）
...
```

主流模型通常使用 8-96 个注意力头，每个头独立学习不同的关注模式。

### 位置编码

Transformer 不像 RNN 那样按顺序处理输入，它需要额外的位置信息来知道每个词在句子中的位置。这就是位置编码（Positional Encoding）的作用。

现代模型通常使用旋转位置编码（RoPE）或相对位置编码，让模型能处理比训练时更长的序列。

## 预训练与微调

大语言模型的训练分为两个阶段：预训练（Pre-training）和微调（Fine-tuning）。

### 预训练

预训练是让模型在海量文本上学习语言的基础规律。训练数据通常来自互联网、书籍、论文、代码库等，规模达到数万亿 token。

预训练的核心任务有两种：

**自回归（Autoregressive）**——给定前面的词，预测下一个词。GPT 系列采用这种方式：

```text
输入:  "今天天气"
预测:  "真" → "今天天气真"
预测:  "好" → "今天天气真好"
```

**掩码语言模型（Masked Language Model）**——遮住句子中的某些词，让模型预测被遮住的词。BERT 采用这种方式：

```text
输入:  "今天 [MASK] 真好"
预测:  [MASK] = "天气"
```

::: tip GPT vs BERT 的区别
GPT 是"从左往右"生成，适合文本生成任务。BERT 是"看全局"理解，适合分类、匹配等理解类任务。今天的大语言模型几乎都采用 GPT 的自回归方式，因为生成能力更通用。
:::

### 微调

预训练后的模型已经具备了通用的语言能力，但在特定任务上可能不够精准。微调就是用少量特定领域的数据，让模型进一步适配你的需求。

常见的微调方式：

| 方式 | 数据量 | 效果 | 成本 |
|------|--------|------|------|
| 全量微调（Full Fine-tuning） | 大量标注数据 | 最好 | 最高（需更新所有参数） |
| LoRA 微调 | 中等数据量 | 接近全量微调 | 较低（只更新少量参数） |
| 指令微调（Instruction Tuning） | 指令-回答对 | 提升指令遵循能力 | 中等 |
| RLHF（人类反馈强化学习） | 人类偏好数据 | 提升有用性和安全性 | 高 |

::: warning 微调不是万能的
如果你的需求可以通过 Prompt 满足，优先用 Prompt。微调需要准备数据、训练模型、部署推理，成本远高于 Prompt Engineering。只有当 Prompt 无法达到要求时，才考虑微调。
:::

## 主流模型架构差异

当前三大模型家族在架构上各有特点：

### GPT 系列（OpenAI）

GPT（Generative Pre-trained Transformer）是纯 Decoder 架构。只使用 Transformer 的解码器部分，自回归地生成文本。

- GPT-4o：多模态原生支持，文本/图像/音频统一处理
- GPT-4o-mini：轻量版，速度更快、成本更低
- 特点：综合能力均衡，API 生态最成熟

### Claude（Anthropic）

Claude 同样基于 Transformer Decoder 架构，但在训练方法上引入了 Constitutional AI（宪法 AI），通过一组原则引导模型自我改进。

- Claude Sonnet：速度与能力的最佳平衡
- Claude Opus：旗舰模型，复杂推理能力最强
- Claude Haiku：轻量快速，适合简单任务
- 特点：长上下文（200K tokens）、指令遵循强、安全设计

### Gemini（Google）

Gemini 是 Google 的原生多模态模型。与其他模型"文本模型 + 多模态扩展"的路线不同，Gemini 从训练开始就同时处理文本、图像、音频和视频。

- Gemini 2.5 Pro：支持 100 万 token 上下文窗口
- Gemini 2.0 Flash：轻量快速版本
- 特点：超长上下文、原生多模态、与 Google 生态深度集成

::: tip 架构差异的实际影响
对使用者来说，架构差异体现在：上下文长度、推理速度、多模态能力和 API 接口。底层架构不同，但使用方式（Prompt + API）是一致的。不必纠结架构细节，关注实际表现即可。
:::

## 模型能力边界

### 能做什么

- **模式匹配与生成**：根据学到的语言模式生成连贯文本
- **知识问答**：回答训练数据中包含的事实性问题
- **代码生成**：根据需求描述编写代码
- **格式转换**：翻译、摘要、格式化
- **简单推理**：逻辑推理、数学计算（中等难度）

### 不能做什么

**幻觉（Hallucination）**：模型会编造看似合理但实际错误的信息。它不知道自己不知道什么。

```text
问: "请介绍一下 2025 年诺贝尔物理学奖得主的研究"
模型可能编造一个不存在的获奖者和研究内容
```

**复杂推理**：多步逻辑推理、高难度数学问题容易出错。模型擅长模式匹配，但不擅长严格的逻辑推演。

**实时信息**：模型的知识截止于训练日期，无法获取最新信息（除非配合搜索工具）。

**精确计算**：模型本质上是概率生成，不是计算器。复杂计算应该交给工具。

**长期记忆**：每次对话都是独立的。模型不会记住你上次对话的内容（除非你主动提供）。

::: warning 永远验证关键信息
在生产环境中使用 LLM 输出时，关键事实必须经过验证。不要把模型的回答当作事实来源，把它当作一个需要审查的初稿。
:::

## 开源 vs 闭源模型

| 维度 | 闭源模型（GPT-4o, Claude, Gemini） | 开源模型（Llama, Qwen, Mistral） |
|------|----------------------------------|--------------------------------|
| 能力上限 | 目前最强 | 接近闭源，差距在缩小 |
| 使用方式 | 只能通过 API 调用 | 可本地部署、可微调 |
| 数据隐私 | 数据发送到第三方服务器 | 数据完全在本地 |
| 成本 | 按 token 计费 | 部署硬件成本高，推理边际成本低 |
| 可定制性 | 有限（Prompt、微调） | 完全可控（架构、训练、推理） |
| 更新频率 | 厂商持续更新 | 社区驱动，更新快 |

::: tip 如何选择
大多数场景下，闭源模型的能力更强、使用更方便。如果你有数据隐私要求、需要深度定制、或者要控制大规模推理成本，开源模型是更好的选择。初学者建议先从闭源 API 开始。
:::

## 模型评测基准

为了客观衡量模型能力，研究社区设计了多种评测基准：

| 基准 | 测什么 | 说明 |
|------|--------|------|
| MMLU | 多领域知识 | 涵盖 57 个学科的选择题，从高中到专业级 |
| HumanEval | 代码生成 | 给定函数签名和文档字符串，生成正确代码 |
| GSM8K | 数学推理 | 小学数学应用题，测试多步推理能力 |
| MATH | 高等数学 | 竞赛级数学问题 |
| MT-Bench | 对话质量 | 多轮对话的有用性、准确性、相关性 |
| HELM | 综合评估 | 覆盖准确性、鲁棒性、公平性、效率等多维度 |

::: warning 排行榜不等于实际体验
基准测试得分高不代表在你的具体任务上表现好。不同的 Prompt、不同的领域，结果可能完全不同。基准分数只做参考，实际测试才是判断标准。
:::

## 涌现能力

当模型的参数量和训练数据量超过某个临界值时，会突然出现一些在小模型上完全看不到的能力，这被称为"涌现能力"（Emergent Abilities）。

```text
参数量 10 亿:  基本能造句，但逻辑混乱
参数量 100 亿: 能做简单的问答和翻译
参数量 1000 亿: 出现链式推理能力，能解多步数学题
参数量 1 万亿+: 出现代码生成、复杂分析等高级能力
```

这就像水烧到 100 度突然沸腾——不是渐变，而是质变。涌现能力的机制目前还没有完全的理论解释，这也是大语言模型让人着迷的原因之一。

::: tip 涌现能力的实际意义
涌现能力意味着：小模型做不到的事，不一定需要渐进式改进，而是可以通过扩大规模直接获得。这也是为什么各大公司竞相训练更大模型的原因。
:::

## 模型规模与效率

### 参数量的意义

模型的参数量（Parameter Count）通常用 B（Billion，十亿）来衡量：

| 模型 | 参数量 | 说明 |
|------|--------|------|
| GPT-4o | 未公开（传闻 200B+） | 闭源，多专家架构 |
| Claude Opus | 未公开 | 闭源 |
| Llama 3 70B | 70B | 开源，可本地部署 |
| Llama 3 8B | 8B | 开源，轻量级 |
| Qwen 2.5 72B | 72B | 开源，中文能力突出 |
| Mistral 7B | 7B | 开源，效率极高 |

参数量越大，模型的容量越高，能学到更复杂的模式。但更大的模型也意味着更高的推理成本和更慢的响应速度。

### 混合专家模型（MoE）

为了让模型既有大容量又保持高效，混合专家模型（Mixture of Experts）应运而生。核心思想是：模型内部有多个"专家网络"，每次只激活其中的几个。

```text
传统密集模型:  所有 1000 亿参数每次都参与计算
MoE 模型:     有 8 个专家（各 1000 亿），每次只激活 2 个
实际计算量:    约 2000 亿参数（而不是 8000 亿）
```

GPT-4 据传就使用了 MoE 架构。这种方式能在保持模型能力的同时大幅降低推理成本。

## 多模态能力

现代 LLM 不仅处理文本，还能理解图像、音频甚至视频，这就是多模态（Multimodal）能力。

### 文本 + 图像

模型可以接收图片并回答关于图片的问题：

```text
输入: [一张代码截图] + "这段代码有什么问题？"
输出: "第 15 行的循环条件应该是 i < len(arr) 而不是 i <= len(arr)，
     这会导致索引越界错误。"
```

### 原生多模态 vs 拼接式多模态

| 方式 | 代表模型 | 原理 |
|------|---------|------|
| 原生多模态 | Gemini | 训练时就同时处理文本、图像、音频 |
| 拼接式多模态 | GPT-4o（早期版本） | 图像通过独立的编码器转换后接入文本模型 |

原生多模态在跨模态理解上通常更强，因为它在训练阶段就学会了不同模态之间的关联。

::: tip 多模态的实用场景
- 截图提 bug：直接截图让模型分析 UI 问题
- 文档理解：上传 PDF/图片，让模型提取关键信息
- 代码辅助：截图转代码、UI 设计稿转前端代码
- 数据可视化：分析图表、生成报告
:::
