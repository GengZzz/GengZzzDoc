# Prompt 基础技巧

Prompt Engineering（提示词工程）是与大语言模型高效沟通的核心技能。一条精心设计的 Prompt 能让模型输出准确、结构化、可用的结果，而一条模糊的 Prompt 则可能得到答非所问的回复。掌握 Prompt 基础技巧，是从"能用 AI"到"用好 AI"的关键一步。

本章将从基本原则出发，逐一讲解 Zero-shot、Few-shot、角色设定、格式控制等核心技巧，并通过正反示例对比帮助你快速建立正确的 Prompt 编写习惯。

## 什么是 Prompt Engineering

Prompt Engineering 是设计和优化输入给大语言模型的指令（Prompt）的过程。其目标是通过精确的文本引导，让模型生成符合预期的输出。

::: tip 为什么重要
同一个模型，Prompt 质量的差异可以让输出质量相差数倍。在生产环境中，Prompt 工程直接决定了 AI 应用的效果上限。投入时间打磨 Prompt，远比更换模型更高效。
:::

## 基本原则

编写 Prompt 需要遵循三个基本原则：明确性、具体性和结构化。

### 明确性

指令必须清晰无歧义，避免模型"猜"你的意图。

**❌ 错误示例：**

```
帮我写一段代码处理数据
```

**✅ 正确示例：**

```
用 Python 编写一个函数，接收一个 CSV 文件路径作为参数，
读取文件内容，按"日期"列排序后，输出为新的 CSV 文件。使用 pandas 库实现。
```

### 具体性

提供足够细节，让模型知道边界和约束。

**❌ 错误示例：**

```
写一篇文章介绍 AI
```

**✅ 正确示例：**

```
撰写一篇面向非技术读者的科普文章，主题是"大语言模型如何工作"。
要求：
- 长度 800-1000 字
- 使用类比方式解释（如"预测下一个词就像自动补全"）
- 避免使用专业术语，必要时用括号附注
- 结尾给出 3 个常见误解及纠正
```

### 结构化

用分隔符、编号、标题等手段组织 Prompt，帮助模型区分指令、上下文和输出要求。

**❌ 错误示例：**

```
帮我分析这个日志文件，找出错误的原因，看看是不是内存泄漏还是配置问题，最后给我一个修复方案
```

**✅ 正确示例：**

```
请分析以下日志文件，完成以下任务：

## 任务
1. 定位错误的根本原因
2. 判断是否为内存泄漏
3. 检查配置是否有异常修改
4. 给出具体的修复方案

## 日志内容
<log>
[粘贴日志内容]
</log>

## 输出要求
按上述任务编号逐一回答，每个问题用 2-3 句话说明。
```

## Zero-shot Prompting

Zero-shot 即"零示例提问"，直接告诉模型任务，不提供任何示例。适用于简单、常见任务。

**❌ 错误示例：**

```
这段话什么意思？
"在量子计算领域，退相干时间是衡量量子比特稳定性的关键指标。"
```

**✅ 正确示例：**

```
请用通俗易懂的语言向高中生解释以下概念的含义：

"在量子计算领域，退相干时间是衡量量子比特稳定性的关键指标。"

要求：不超过 100 字，可使用类比。
```

**代码重构示例：**

```
将以下 JavaScript 函数重构为使用 async/await 语法，保持功能不变：

function fetchUser(id) {
  return fetch('/api/users/' + id)
    .then(res => res.json())
    .then(data => data.user)
    .catch(err => console.error(err));
}
```

## Few-shot Prompting

Few-shot 即"少样本提问"，通过提供若干输入-输出示例，让模型学习任务模式。适用于需要特定风格或格式的任务。

**示例 1 — 情感分析：**

```
请按照以下示例，判断用户评论的情感倾向。

示例：
评论：这个产品用了一个月就坏了，太失望了。
情感：负面

评论：物流很快，包装也很好，非常满意！
情感：正面

评论：一般般吧，没什么特别的，用着还行。
情感：中性

现在请判断：
评论：质量不错，就是价格有点贵，希望能做活动。
情感：
```

**示例 2 — 实体提取：**

```
从文本中提取人名、地名和组织名，按 JSON 格式输出。

文本：张伟在北京大学读博士，毕业后加入了位于上海的阿里巴巴集团。
结果：
{
  "人名": ["张伟"],
  "地名": ["北京", "上海"],
  "组织名": ["北京大学", "阿里巴巴集团"]
}

文本：李娜和王强一起在清华大学参加了华为举办的编程比赛。
结果：
```

**示例 3 — 代码注释风格：**

```
请按照以下示例的注释风格，为新函数添加注释。

示例：
// calculateSum: 计算整数数组所有元素之和
// @param {number[]} nums - 输入的整数数组
// @returns {number} - 数组元素之和
function calculateSum(nums) { ... }

请为以下函数添加注释：
function debounce(fn, delay) { ... }
```

::: warning 注意事项
Few-shot 示例的数量建议 3-5 个，过少模型学不到模式，过多会占用上下文长度。示例应覆盖边界情况，以提高鲁棒性。
:::

## 角色设定（Role Prompting）

角色设定通过在 Prompt 开头为模型指定一个身份或专业角色，引导其以特定视角和知识水平生成内容。

### 系统提示词的写法

```
你是一位有 10 年经验的高级后端工程师，擅长 Go 语言和分布式系统设计。

你的职责：
1. 审查用户提交的 Go 代码，指出潜在问题
2. 用简洁的技术语言给出修改建议
3. 对每个问题标注严重等级：[严重] [警告] [建议]

注意事项：
- 只关注代码质量和架构问题，不做功能实现
- 每条建议必须引用具体代码行
```

**❌ 错误示例（角色设定过于模糊）：**

```
你是一个专家，请帮我看看这段代码
```

**✅ 正确示例（角色设定明确）：**

```
你是一位专注于性能优化的数据库专家，精通 MySQL 和 PostgreSQL。

请分析以下 SQL 查询的性能问题：

SELECT u.name, COUNT(o.id)
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE u.created_at > '2024-01-01'
GROUP BY u.name
ORDER BY COUNT(o.id) DESC;

要求：
1. 分析查询计划中可能的性能瓶颈
2. 给出索引建议
3. 如有必要，重写 SQL 语句
```

| 角色类型 | 适用场景 | 示例 |
|---------|---------|------|
| 技术专家 | 代码审查、架构设计 | "你是一位分布式系统架构师" |
| 教育者 | 知识讲解、学习辅导 | "你是一位擅长用类比教学的计算机教授" |
| 编辑 | 文章润色、翻译 | "你是一位严谨的科技媒体编辑" |
| 批判者 | 风险评估、漏洞分析 | "你是一位安全审计员" |

## 输出格式控制

明确指定输出格式，可以让模型的回复直接用于下游处理。

### JSON 格式

```
从以下用户描述中提取订单信息，以 JSON 格式输出。

用户描述："我要买 3 件红色的 L 码 T 恤，收货地址是北京市朝阳区，用优惠券 SAVE20。"

输出格式：
{
  "items": [{"name": "", "color": "", "size": "", "quantity": 0}],
  "address": "",
  "coupon": ""
}
```

### Markdown 表格格式

```
将以下编程语言按照"学习难度"、"就业需求"和"典型用途"三个维度进行对比。

编程语言：Python、Rust、JavaScript、Go

输出为 Markdown 表格：
| 语言 | 学习难度 | 就业需求 | 典型用途 |
|------|---------|---------|---------|
```

**❌ 错误示例（格式要求不明确）：**

```
把数据整理一下发给我
```

**✅ 正确示例（格式要求明确）：**

```
将以下数据整理为 CSV 格式，包含表头，字段用逗号分隔：

数据：Python 2024 年排名第一，市场份额 28%；JavaScript 排名第二，份额 22%；Java 排名第三，份额 15%。

输出格式示例：
排名,语言,年份,市场份额
1,Python,2024,28%
```

## 常见错误与避免方法

### 模糊指令

**❌ 错误：** `帮我优化一下`

**✅ 正确：**

```
请优化以下 Python 函数的执行效率，当前处理 100 万条记录需要 45 秒，目标缩短到 5 秒以内。
代码：[粘贴代码]
```

### 过度约束

**❌ 错误：** 约束过多反而限制模型发挥

```
写一篇博客，必须用 7 段，每段 3-5 句话，第一段必须以问句开头，最后一段必须以名言结尾...
```

**✅ 正确：** 保留关键约束

```
写一篇关于 Docker 容器化优势的技术博客。目标读者：有 Linux 基础的后端开发者，篇幅 1500 字左右。
```

### 忽略上下文

**❌ 错误：** 假设模型知道之前聊了什么

```
那把它改成支持并发的版本
```

**✅ 正确：** 提供必要上下文

```
基于以下函数，将其改造为支持并发执行的版本，使用 concurrent.futures，最大并发数为 4。

def process_files(file_list):
    for f in file_list:
        data = read_csv(f)
        result = analyze(data)
        save(result)
```

## 实用模板

### 模板 1：代码生成

```
请用 {语言} 编写一个 {功能描述}。
要求：
- 输入：{描述输入参数}
- 输出：{描述返回值}
- 异常处理：{描述错误处理方式}
- 依赖：{列出可使用的库/框架}

请包含完整的函数实现、行内注释和 3 个以上的单元测试用例。
```

### 模板 2：文章写作

```
撰写一篇关于 {主题} 的技术文章。
目标读者：{读者画像}
篇幅：{字数要求}
结构：引言 → 核心内容 → 实践步骤 → 学习建议
风格：{简洁/详细/科普/学术}
```

### 模板 3：数据分析

```
请分析以下数据，完成：
1. 基础统计：均值、中位数、标准差
2. 趋势分析：时间维度上的主要趋势
3. 异常检测：偏离正常范围的数据点

数据：{粘贴数据}
输出：先文字总结，再附详细数据表。
```

### 模板 4：翻译

```
将以下 {源语言} 技术文档翻译为 {目标语言}。
- 保留所有代码块，不做翻译
- 技术术语保留英文并用括号标注中文，如：dependency injection（依赖注入）
- 保持 Markdown 格式

原文：{粘贴原文}
```

### 模板 5：摘要提取

```
请为以下内容生成结构化摘要：
1. 一句话总结核心观点（不超过 50 字）
2. 3-5 个要点，每点 1-2 句话
3. 关键数据单独列出

内容：{粘贴内容}
```

::: tip 使用建议
以上模板中的 `{占位符}` 需要根据实际场景替换。建议将常用模板保存为代码片段，在需要时快速调用并按需修改。
:::
