# AI 入门

从零开始理解人工智能：它是什么、怎么发展到今天、以及你该如何学习。

## 什么是人工智能

人工智能（Artificial Intelligence, AI）是让机器模拟人类智能行为的技术总称。从最早的专家系统，到今天能写代码、画图、对话的大语言模型，AI 经历了三次重要的发展浪潮。

### 三次浪潮

**第一次浪潮：符号主义（1950s-1980s）**

核心思路是用逻辑规则和符号推理来模拟人类思维。研究者手写大量 "if-then" 规则，让机器按规则推导结论。

```text
规则示例：
IF 动物有羽毛 AND 会飞 THEN 是鸟类
IF 动物有羽毛 AND 不会飞 THEN 可能是企鹅
```

优势是推理过程可解释，但现实世界的规则太多太复杂，手写规则根本写不完。这波浪潮在 1980 年代末逐渐冷却。

**第二次浪潮：机器学习（1990s-2010s）**

不再手写规则，而是让机器从数据中自动学习规律。核心范式是：给机器大量标注数据，让它自己找到输入和输出之间的映射关系。

```text
传统编程:  数据 + 规则 → 结果
机器学习:  数据 + 结果 → 规则
```

代表性算法包括决策树、支持向量机（SVM）、随机森林等。这波浪潮让垃圾邮件过滤、推荐系统、信用评分等应用成为现实。

**第三次浪潮：深度学习（2012-至今）**

用多层神经网络（深度网络）来学习数据的层次化特征表示。2012 年 AlexNet 在图像识别竞赛中大幅领先传统方法，标志着深度学习时代的开始。

```text
输入图片 → 边缘检测 → 纹理识别 → 部件组合 → 物体识别
  第1层      第2层       第3层       第4层      输出层
```

GPU 算力的爆发和海量数据的积累，让深层网络的训练成为可能。今天的 GPT、Claude、Gemini 都是深度学习的产物。

::: tip 关键转折点
2017 年 Google 发表论文《Attention Is All You Need》，提出 Transformer 架构。这个架构彻底改变了 NLP 领域，也是今天所有大语言模型的基础。
:::

## 大语言模型是什么

大语言模型（Large Language Model, LLM）是深度学习在自然语言处理领域的最新成果。它通过在海量文本上训练，学习语言的统计规律，从而能够理解和生成人类语言。

核心原理可以用一句话概括：**给定前面的文字，预测下一个最可能出现的词。**

```text
输入:  "Python 中处理 HTTP 请求最常用的库是"
模型:  P("requests")=0.72, P("urllib")=0.18, P("flask")=0.06, ...
输出:  "requests"
```

这听起来简单，但当模型足够大、数据足够多时，这个"预测下一个词"的能力就涌现出了令人惊讶的智能行为——推理、编程、翻译、创作。

### LLM 能做什么

- **文本生成**：写文章、邮件、报告、代码
- **对话问答**：理解问题并给出有条理的回答
- **代码辅助**：生成、审查、调试、重构代码
- **翻译与摘要**：多语言翻译、长文总结
- **数据分析**：理解数据、生成分析报告
- **逻辑推理**：数学证明、因果分析、决策辅助

::: warning 模型不是万能的
LLM 没有真正的"理解"，它的回答基于统计规律而非事实。因此它会一本正经地胡说八道（幻觉）、对复杂推理容易出错、无法获取训练数据之外的信息。了解模型的边界，才能用好它。
:::

## 为什么现在要学 AI

**AI 不是未来的趋势，而是当下的现实。** 2023 年以来，AI 已经深度嵌入到软件开发的各个环节：

- GitHub Copilot 月活用户超过百万，代码补全成为日常
- Claude Code、Cursor 等工具改变了代码编写方式
- 大量公司要求开发者具备 AI 工具使用能力

::: tip 不需要成为 AI 专家
学习 AI 不是要你去训练模型或写论文。对大多数开发者来说，核心需求是三件事：

1. 理解模型能做什么、不能做什么
2. 写好 Prompt 让模型输出高质量结果
3. 把 AI 能力通过 API 集成到自己的项目中

这三件事，本系列文档都会覆盖。
:::

掌握 AI 工具的开发者，效率可以提升数倍。不掌握的，会在竞争中逐渐落后。这就是现在要学的理由。

## 常见误解澄清

### "AI 会取代程序员"

AI 改变的是程序员的工作方式，而不是取代程序员。就像编译器没有取代程序员、IDE 没有取代程序员一样，AI 工具是生产力放大器。会用 AI 的程序员会取代不会用的——这和任何技术变革的规律一致。

```text
过去:  手写汇编 → 高级语言 → 框架 → AI 辅助
每次变革: 消除重复劳动，让人专注更高层的设计和决策
```

### "AI 生成的代码可以直接用"

AI 生成的代码质量参差不齐。它可能在简单任务上表现完美，也可能在复杂业务逻辑中引入难以发现的 bug。正确的使用方式是：把 AI 当作一个高效的初稿生成器，你负责审查、测试和优化。

::: warning 生产环境必须审查
AI 生成的代码在提交到生产环境之前，必须经过人工审查和充分测试。不要跳过 Code Review 环节。
:::

### "越大的模型越好"

模型大小和任务难度需要匹配。用 GPT-4o 处理简单的文本分类任务，就像用大炮打蚊子——效果不一定更好，成本却高很多。日常任务用轻量模型（GPT-4o-mini、Claude Haiku、Gemini Flash）就够，复杂推理才需要旗舰模型。

## 核心术语速查

在阅读后续文档之前，先了解这些常用术语：

| 术语 | 含义 |
|------|------|
| LLM | 大语言模型（Large Language Model） |
| Token | 模型处理文本的最小单位 |
| Prompt | 发送给模型的输入文本 |
| Context Window | 模型单次能处理的最大 token 数 |
| Temperature | 控制输出随机性的参数 |
| Inference | 模型生成回答的过程（推理） |
| Fine-tuning | 用特定数据对预训练模型进行微调 |
| RAG | 检索增强生成，先检索再让模型回答 |
| Agent | 让模型自主调用工具完成任务的架构 |
| Hallucination | 模型编造不实信息（幻觉） |
| Embedding | 将文本转换为向量表示 |
| API | 应用程序接口，用于程序化调用模型 |

## 快速上手

在深入了解原理之前，你可以先通过以下方式体验 AI 的能力。

### 方式一：网页对话

最简单的方式是直接使用各厂商提供的网页界面：

- **ChatGPT**：[chat.openai.com](https://chat.openai.com) — 综合能力最均衡
- **Claude**：[claude.ai](https://claude.ai) — 长文本处理和代码能力突出
- **Gemini**：[gemini.google.com](https://gemini.google.com) — 多模态能力强，与 Google 生态集成

注册后即可免费使用基础模型。建议每个都试一下，感受不同模型的风格差异。

### 方式二：API 调用

如果你是开发者，API 调用是最有价值的方式。一个最小示例：

```python
import openai

client = openai.OpenAI(api_key="your-api-key")

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "用一句话解释什么是 Transformer 架构"}
    ]
)

print(response.choices[0].message.content)
```

详细的 API 接入方法，参见 [API 接入](./api-integration.md)。

### 方式三：IDE 集成

在开发环境中直接使用 AI 辅助编码：

- **GitHub Copilot**：VS Code / JetBrains 插件，代码自动补全
- **Cursor**：内置 AI 的代码编辑器
- **Claude Code**：终端中的 AI 编程助手

::: tip 从对话开始
如果你是初学者，建议从网页对话开始。先学会写好 Prompt，再过渡到 API 和工具集成。理解 Prompt 是使用所有 AI 工具的基础。
:::

## AI 在实际开发中的角色

AI 在软件开发中可以承担多种角色，从辅助到自主，逐步升级：

```text
Level 1 - 自动补全
  Copilot 在你编码时实时建议代码片段
  你需要：审查每一行建议

Level 2 - 问答助手
  遇到问题时向 AI 提问，获取解答和代码示例
  你需要：验证答案的正确性

Level 3 - 任务执行者
  给 AI 一个明确任务，它生成完整实现
  你需要：定义需求、审查结果、运行测试

Level 4 - 协作伙伴（Agent）
  AI 自主拆解任务、调用工具、迭代改进
  你需要：设定目标、审核最终结果

Level 5 - 自主系统
  多个 Agent 协作完成端到端任务
  你需要：设计架构、监督流程
```

目前大多数开发者处于 Level 1-3，Level 4（Agent）正在快速成熟。本系列文档将帮你从 Level 1 逐步走向 Level 4。建议按顺序阅读，每读完一节就动手实践，学以致用效果最好。
