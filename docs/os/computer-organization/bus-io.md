# 总线与 I/O 系统

总线是各部件间信息传输的公共通道，I/O 系统负责主机与外部设备的数据交换。408 考试重点考查总线仲裁、总线定时、I/O 方式。

## 总线概述

### 总线分类

| 分类 | 说明 | 典型 |
|------|------|------|
| 按功能 | 数据总线（双向）、地址总线（单向）、控制总线（部分双向） | — |
| 按位置 | 片内总线、系统总线、通信总线 | — |
| 按数据传输 | 并行总线、串行总线 | PCI（并行）、USB（串行） |

### 总线结构

```text
单总线结构:
  CPU ←→ 主存 ←→ I/O 设备
  简单但带宽瓶颈

双总线结构:
  CPU ←→ 主存总线 ←→ 主存
  CPU ←→ I/O 总线  ←→ I/O 设备
  增加通道或桥接

三总线结构:
  CPU ←→ 主存
  CPU ←→ I/O 总线 ←→ I/O 设备
  主存 ←→ DMA 总线  ←→ 高速 I/O
```

## 总线仲裁

多个设备同时请求总线时，需要仲裁决定谁获得使用权。

### 集中式仲裁

| 方式 | 原理 | 特点 |
|------|------|------|
| 链式查询 | BG 信号沿设备链传递，离仲裁器近的优先级高 | 简单，但优先级固定，对故障敏感 |
| 计数器定时 | 维护计数器，从计数器值开始依次查询 | 优先级灵活，速度中等 |
| 独立请求 | 每个设备有独立的 BR/BG 线 | 速度快，但线数多 |

```text
链式查询:
  仲裁器 → BG → 设备0 → 设备1 → 设备2 → ...
              ↓       ↓       ↓
             BR ←────┴───────┘

独立请求:
  设备0: BR₀ → 仲裁器 ← BG₀
  设备1: BR₁ → 仲裁器 ← BG₁
  设备2: BR₂ → 仲裁器 ← BG₂
```

::: tip 三种方式对比
链式查询硬件最少但优先级不可变；独立请求速度最快但成本最高；计数器定时是折中方案。
:::

### 分布式仲裁

没有中央仲裁器，各设备自行协商。每个设备将自己的仲裁号发送到总线上，与总线上的值比较，最终最高优先级的设备获得总线。

## 总线定时

总线定时定义了总线上各事件的时序关系。

### 同步定时

所有设备共用统一时钟。

```text
时钟:  ──┐  ┌──┐  ┌──┐  ┌──
         └──┘  └──┘  └──┘

T₁:    发送地址
T₂:    发送数据
T₃:    读/写操作
T₄:    数据有效 / 撤销
```

**优点**：简单、速度快。**缺点**：设备必须按最慢的设备统一频率。

### 异步定时

用握手信号（请求/应答）协调，不依赖统一时钟。

```text
互锁方式（最常用）:

主设备: ──请求──────────┐
                       ↓
从设备:      ──应答──┐  │
                    └──┘
                     ↓
主设备: ────────────撤销请求
```

**优点**：允许不同速度的设备。**缺点**：握手开销大，速度较慢。

### 半同步定时

在同步总线基础上增加 WAIT 信号，慢设备可插入等待周期。

## 总线标准

| 标准 | 说明 |
|------|------|
| ISA | 工业标准，16 位，已淘汰 |
| PCI | 并行，32/64 位，即插即用 |
| PCI Express | 串行点对点，取代 PCI |
| AGP | 图形加速专用，已被 PCIe 取代 |
| USB | 通用串行总线，热插拔 |
| SATA | 串行 ATA，硬盘接口 |

## I/O 系统

### I/O 接口

I/O 接口（I/O 控制器）是 CPU 与 I/O 设备之间的桥梁。

```text
┌──────────────────────────────┐
│          I/O 接口             │
│                              │
│  ┌──────┐  ┌──────┐         │
│  │数据寄存│  │状态寄存│        │
│  └──────┘  └──────┘         │
│  ┌──────┐  ┌──────┐         │
│  │控制寄存│  │中断逻辑│        │
│  └──────┘  └──────┘         │
│                              │
│  数据线 ←→ CPU 总线          │
│  地址线 ←→ 设备              │
└──────────────────────────────┘
```

### I/O 方式

#### 程序查询方式

CPU 不断轮询设备状态寄存器，设备准备好才传输。

```text
CPU: 读状态 → 忙则等待 → 就绪则读/写数据 → 循环

优点: 简单，不需要额外硬件
缺点: CPU 全程参与，利用率极低
```

#### 程序中断方式

设备准备好后主动通知 CPU。

```text
设备: 数据就绪 → 发中断请求
CPU: 响应中断 → 保存断点 → 转中断服务 → 读/写数据 → 返回

优点: CPU 不用等待，利用率提高
缺点: 每次传输都要中断，频繁中断仍占用 CPU
```

#### DMA 方式

DMA 控制器直接在内存和设备间传输数据，不经过 CPU。

```text
┌──────┐    ──────    ┌──────┐
│  CPU │ ←→ │ 总线 │ ←→ │ DMA  │ ←→ I/O 设备
└──────┘    ──────    │控制器│
              ↑       └──────┘
            主存

DMA 传输过程:
1. CPU 向 DMA 控制器设置: 源地址、目标地址、传输字节数
2. DMA 控制器接管总线，直接与主存交换数据
3. 传输完毕，DMA 向 CPU 发中断

优点: 数据传输不占用 CPU
缺点: 需要额外硬件（DMA 控制器）
```

**DMA 与 CPU 对总线的冲突**：

| 方式 | 说明 |
|------|------|
| 停止 CPU | DMA 传输期间 CPU 停止访存，简单但浪费 CPU |
| 周期挪用 | DMA 在 CPU 不访存时（空闲周期）使用总线 |
| 交替访问 | CPU 和 DMA 分时交替，不冲突但需要双端口存储器 |

::: tip 三种 I/O 方式对比
| 对比 | 程序查询 | 程序中断 | DMA |
|------|---------|---------|-----|
| CPU 参与度 | 全程 | 每次传输 | 仅设置参数 |
| 适用场景 | 低速简单设备 | 中低速设备 | 高速批量传输 |
| 数据单位 | 字 | 字 | 数据块 |
:::

### 通道方式

通道是比 DMA 更高级的 I/O 处理器，有自己的指令系统，可独立执行 I/O 程序。

| 通道类型 | 数据传输单位 |
|----------|------------|
| 字节多路通道 | 字节，多设备交叉 |
| 数组多路通道 | 数据块，多设备交叉 |
| 选择通道 | 数据块，独占通道 |

## 高频考点总结

| 考点 | 频率 | 说明 |
|------|------|------|
| 三种仲裁方式对比 | 高 | 链式/计数器/独立请求 |
| 同步 vs 异步定时 | 中 | 握手协议 |
| 程序中断 vs DMA | 极高 | 流程、适用场景、区别 |
| DMA 三种方式 | 高 | 停止 CPU/周期挪用/交替 |
| I/O 接口功能 | 中 | 数据/状态/控制寄存器 |
