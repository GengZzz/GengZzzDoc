# 指令系统

指令系统（Instruction Set）是软硬件之间的接口。408 考试重点考查指令格式、寻址方式、CISC 与 RISC 的区别。

## 指令格式

一条指令包含操作码（做什么）和地址码（操作数在哪）。

### 按地址码数目分类

| 类型 | 格式 | 说明 |
|------|------|------|
| 零地址 | OP | 无操作数（如 NOP、停机），或操作数隐含（栈顶） |
| 一地址 | OP A | 单操作数运算（如取反、加 1），或另一操作数隐含在 ACC |
| 二地址 | OP A₁ A₂ | A₁ 既是操作数又是结果存放处：A₁ ← (A₁) OP (A₂) |
| 三地址 | OP A₁ A₂ A₃ | A₃ ← (A₁) OP (A₂)，A₁ A₂ 不被破坏 |

::: tip 零地址指令的典型场景
运算器以累加器 ACC 为隐含操作数；或者基于栈的指令集（如 JVM 字节码），操作数总在栈顶。
:::

### 扩展操作码

固定长度的操作码限制指令数量。扩展操作码让短指令的操作码短、长指令的操作码长，兼顾指令数和地址码位数。

```text
例：16 位指令，4 个 4 位字段

三地址指令: [OP(4位)] [A1(4)] [A2(4)] [A3(4)]
  操作码 0000~1110 → 15 条三地址指令
  操作码 1111 → 扩展为二地址指令

二地址指令: [1111] [OP(4位)] [A1(4)] [A2(4)]
  操作码 1111 0000~1111 1110 → 15 条二地址指令
  操作码 1111 1111 → 继续扩展

一地址指令: [1111] [1111] [OP(4位)] [A1(4)]
  ...以此类推
```

::: warning 设计约束
扩展操作码时，必须保证短指令的操作码不是长指令操作码的前缀，否则无法译码。设计时从全 0 或全 1 开始预留扩展空间。
:::

### 指令字长

| 方式 | 说明 |
|------|------|
| 定长指令字长 | 所有指令长度相同，便于译码和取指 |
| 变长指令字长 | 按需分配，节省存储空间，但译码复杂 |

现代处理器通常采用**定长操作码 + 可变操作数**的混合方式。

## 寻址方式

寻址方式决定如何从指令中的地址信息找到操作数或跳转目标。

### 数据寻址

| 方式 | 格式 | 说明 | 有效地址 EA |
|------|------|------|------------|
| 立即寻址 | #A | A 就是操作数本身 | 无需 EA |
| 直接寻址 | A | A 是操作数的地址 | EA = A |
| 间接寻址 | (A) | A 存放的是地址的地址 | EA = (A) |
| 寄存器寻址 | R | 操作数在寄存器 R 中 | 无需 EA |
| 寄存器间接寻址 | (R) | 寄存器中存的是操作数地址 | EA = (R) |
| 隐含寻址 | — | 操作数隐含在 ACC 等 | 无需 EA |

### 偏移寻址

| 方式 | 说明 | 有效地址 EA |
|------|------|------------|
| 基址寻址 | 基址寄存器 BR + 形式地址 A | EA = (BR) + A |
| 变址寻址 | 变址寄存器 IX + 形式地址 A | EA = (IX) + A |
| 相对寻址 | PC + 形式地址 A | EA = (PC) + A |

::: tip 基址 vs 变址
- **基址寻址**：BR 内容由 OS 设定，用户只改 A。用于程序重定位和多道程序。
- **变址寻址**：A 不变，用户改 IX。典型场景：数组遍历 `A[0] → A[1] → ...`，每次 IX+1。
- 两者可组合：`EA = (BR) + (IX) + A`
:::

### 堆栈寻址

操作数在栈顶，指令隐含访问 SP 所指位置。分为：
- **硬堆栈**：用寄存器组实现，速度快
- **软堆栈**：在主存中实现，容量大

## CISC 与 RISC

| 对比 | CISC（复杂指令集） | RISC（精简指令集） |
|------|-------------------|-------------------|
| 指令数目 | 多，数百条 | 少，通常 < 100 条 |
| 指令格式 | 变长 | 定长（通常 32 位） |
| 寻址方式 | 多 | 少 |
| 指令周期 | 差异大，多周期 | 单周期或流水线 |
| 控制方式 | 微程序为主 | 硬布线为主 |
| 通用寄存器 | 少 | 多 |
| 程序代码量 | 小 | 大（同一功能需更多指令） |
| 典型代表 | x86 | ARM、MIPS、RISC-V |

::: tip 两者的融合趋势
现代处理器表面上是 CISC（x86 指令集），内部将 CISC 指令解码为类似 RISC 的微操作（μop）执行。这说明 RISC 的硬件设计理念已被广泛采纳。
:::

## 指令执行过程

### 指令周期

```text
一条指令的执行：

取指 → 译码 → 执行 → （访存）→ （写回）

取指: 从 (PC) 指向的地址取指令 → 存入 IR
译码: 分析操作码和操作数，生成控制信号
执行: ALU 计算或访存
访存: Load/Store 指令需要读写内存
写回: 结果写入寄存器或内存
```

### 数据通路

```text
                ┌────────────┐
                │    CPU      │
  ┌────────┐   │  ┌──────┐   │
  │  PC    │──→│  │  ALU │   │
  └────────┘   │  └──┬───┘   │
  ┌────────┐   │     │       │
  │  IR    │──→│  译码器     │
  └────────┘   │     │       │
  ┌────────┐   │  ┌──┴───┐   │
  │ 寄存器堆│←──│  │控制单元│  │
  └────────┘   │  └──────┘   │
       ↕       └──────┬──────┘
  ┌────────┐          │
  │  MAR   │←─────────┘
  └───┬────┘
      ↓
  ┌────────┐
  │  MDR   │←──→ 主存
  └────────┘
```

### 指令流水线

将指令执行分为若干阶段，各阶段并行工作：

```text
时间 →  T1    T2    T3    T4    T5    T6    T7
指令1: 取指 → 译码 → 执行 → 访存 → 写回
指令2:       取指 → 译码 → 执行 → 访存 → 写回
指令3:             取指 → 译码 → 执行 → 访存 → 写回
```

**理想加速比** = 流水线段数（5 段流水线理论加速 5 倍）

**实际瓶颈**：
- **结构冲突**：多条指令同时使用同一资源
- **数据冲突**：后一条指令依赖前一条的结果
- **控制冲突**：遇到转移指令，预取的后续指令可能无用

解决方法：暂停（stall）、数据前推（forwarding）、分支预测
