# 内存管理

内存管理负责将有限的物理内存分配给多个进程。408 考试重点考查分页管理、地址转换、页面置换算法。

## 内存管理基础

### 连续分配

每个进程占用一段连续的内存空间。

| 方式 | 说明 |
|------|------|
| 单一连续分配 | 只有一个用户进程，简单但浪费 |
| 固定分区分配 | 内存分为若干固定大小的分区 |
| 动态分区分配 | 按需分配，产生外部碎片 |

**动态分区分配算法**：

| 算法 | 策略 |
|------|------|
| 首次适应 | 从头找第一个够大的空闲区 |
| 最佳适应 | 找最小的够大的空闲区（空闲区按大小排序） |
| 最坏适应 | 找最大的空闲区 |
| 下次适应 | 从上次分配位置继续找 |

::: tip 外部碎片 vs 内部碎片

- **外部碎片**：空闲分区太小无法使用（连续分配的问题）
- **内部碎片**：分配的分区大于实际需求（分页的问题）
:::

### 非连续分配

进程可以分散存储在不连续的内存块中。

## 分页存储管理

### 基本原理

将内存分为固定大小的**页框（物理块）**，将进程的逻辑地址空间分为相同大小的**页**。

```text
逻辑地址空间:           物理内存:
┌────────┐            ┌────────┐
│  页 0  │──────────→ │ 块 3   │
├────────┤            ├────────┤
│  页 1  │───────┐    │ 块 7   │
├────────┤       │    ├────────┤
│  页 2  │─┐     └──→ │ 块 1   │
├────────┤ │          ├────────┤
│  页 3  │ └────────→ │ 块 5   │
└────────┘            └────────┘
```

### 地址转换

```text
逻辑地址: ┌────────────┬──────────────┐
          │  页号 P    │  页内偏移 W  │
          └──────┬─────┴──────────────┘
                 ↓
              查页表
                 ↓
物理地址: ┌────────────┬──────────────┐
          │ 帧号 F     │  页内偏移 W  │
          └────────────┴──────────────┘

物理地址 = 帧号 × 页大小 + 页内偏移
```

**页号和偏移的划分**：若页面大小为 4KB（2¹²），则低 12 位为页内偏移，高位为页号。

::: tip 例题
某系统页面大小 4KB，逻辑地址 0x12345678，求页号和偏移。

页内偏移 = 低 12 位 = 0x678
页号 = 高 20 位 = 0x12345
:::

### 快表 TLB

页表在内存中，每次地址转换需访问两次内存（查页表 + 访问数据）。TLB（快表）是页表的 Cache。

```text
有 TLB 的访问流程:
1. 取逻辑地址的页号
2. 查 TLB
   命中 → 直接获得帧号（1 次访存）
   未命中 → 查内存页表 → 更新 TLB → 访问数据（2 次访存）
3. 组合物理地址，访问数据

有效访问时间 EAT:
EAT = α × (t_TLB + t_mem) + (1-α) × (t_TLB + 2×t_mem)
α 为 TLB 命中率
```

### 多级页表

页表本身可能很大，需要分页存储。

```text
二级页表:
逻辑地址: ┌──────────┬──────────┬──────────┐
          │ 一级页号  │ 二级页号  │ 页内偏移  │
          └────┬─────┴────┬─────┴──────────┘
               ↓          ↓
          查一级页表 → 得到二级页表地址
                      → 查二级页表 → 得到帧号

访存次数: 一级 → 1次, 二级 → 2次, n级 → n+1次（无 TLB）
```

::: warning 多级页表的代价
多级页表减少了页表占用的空间（未使用的页可以不分配二级页表），但增加了访存次数。TLB 的命中率变得更为关键。
:::

## 分段存储管理

按程序的逻辑结构划分为若干段（代码段、数据段、栈段等）。

```text
逻辑地址: ┌──────────┬──────────────┐
          │  段号 S   │  段内偏移 W  │
          └────┬─────┴──────────────┘
               ↓
            查段表
          ┌──────────┬──────────┐
          │ 段基址    │ 段长     │
          └──────────┴──────────┘
               ↓
物理地址 = 段基址 + W （需检查 W < 段长）
```

| 对比 | 分页 | 分段 |
|------|------|------|
| 划分依据 | 物理等分 | 逻辑划分 |
| 大小 | 固定 | 可变 |
| 碎片 | 内部碎片 | 外部碎片 |
| 用户可见 | 不可见 | 可见 |
| 优点 | 无外部碎片 | 符合程序逻辑，便于共享和保护 |

## 段页式管理

结合分段和分页的优点：先分段，段内再分页。

```text
逻辑地址: ┌──────────┬──────────┬──────────┐
          │  段号 S   │  页号 P  │ 页内偏移 W │
          └────┬─────┴────┬─────┴──────────┘
               ↓          ↓
          查段表 → 得到该段的页表起始地址
                   → 查页表 → 得到帧号
                              → 组合物理地址

访存次数: 3 次（无 TLB），有 TLB 可减少到 1~2 次
```

## 虚拟内存

### 基本原理

虚拟内存让进程认为有连续的大地址空间，实际只将部分页面装入物理内存。

```text
请求调页: 访问的页不在内存时，从外存调入
页面置换: 内存满时，换出某页给新页腾空间
```

### 页面置换算法

| 算法 | 规则 | 说明 |
|------|------|------|
| OPT | 淘汰未来最久不使用的 | 最优但无法实现，作为理论基准 |
| FIFO | 淘汰最早进入内存的 | 简单但有 **Belady 异常** |
| LRU | 淘汰最近最久未使用的 | 效果好，实现开销大 |
| Clock（NRU） | 循环扫描，淘汰访问位为 0 的 | LRU 的近似实现 |

::: tip Belady 异常
FIFO 算法可能出现分配的物理块越多缺页次数反而越多的异常现象。LRU 和 OPT 不会出现此异常。
:::

### Clock 算法（近似 LRU）

```text
页面组成一个环形链表，每个页面有一个访问位

第一轮: 顺时针扫描
  访问位 = 1 → 清零，跳过
  访问位 = 0 → 淘汰该页

如果所有页面访问位都是 1（第一轮没找到）：
  第二轮：所有页面访问位已清零，淘汰第一个遇到的页面
```

### 页面置换例题

```text
页面访问序列: 1 2 3 4 1 2 5 1 2 3 4 5
物理块数: 3

FIFO:
  1 2 3 → 4换1 → 1换2 → 2换3 → 5换4 → ...
  共 9 次缺页

LRU:
  1 2 3 → 4换1 → 1换2 → 2换3 → 5换4 → ...
  共 10 次缺页（需根据"最近使用"顺序判断）
```

### 工作集与抖动

**抖动（Thrashing）**：频繁的页面置换导致系统忙于换页，CPU 利用率急剧下降。

**工作集**：进程在某段时间内访问的页面集合。工作集窗口大小影响分配的物理块数。

```text
解决抖动:
1. 控制并发进程数（工作集策略）
2. 局部置换（进程只能淘汰自己的页面）
3. 预留部分空闲帧
```

## 高频考点总结

| 考点 | 频率 | 说明 |
|------|------|------|
| 分页地址转换 | 极高 | 页号、偏移、物理地址计算 |
| 页面置换算法 | 极高 | FIFO、LRU、Clock 的缺页次数 |
| TLB + 有效访问时间 | 高 | 含 TLB 的 EAT 计算 |
| 段页式管理 | 高 | 地址结构、访存次数 |
| Belady 异常 | 中 | FIFO 特有问题 |
| 抖动与工作集 | 中 | 概念和解决方法 |
