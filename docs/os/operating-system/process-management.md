# 进程管理

进程管理是操作系统的核心，408 考试分值最高。重点考查进程调度、同步互斥（PV 操作）、死锁。

## 进程与线程

### 进程的概念

进程是程序的一次执行过程，是系统进行资源分配和调度的基本单位。

```text
进程控制块 PCB:
┌──────────────────────────┐
│ 进程标识符 PID            │
│ 进程状态（就绪/运行/阻塞） │
│ 程序计数器 PC             │
│ 寄存器现场                │
│ 内存管理信息（页表等）     │
│ I/O 状态信息              │
│ 进程优先级                │
│ 父进程/子进程关系          │
└──────────────────────────┘
```

### 进程状态与转换

```text
          创建
           ↓
        ┌──────┐
        │ 就绪 │←────────┐
        └──┬───┘         │
           ↓ 调度        │ 时间片用完
        ┌──────┐         │
        │ 运行 │─────────┘
        └──┬───┘
           ↓ I/O 请求或等待事件
        ┌──────┐
        │ 阻塞 │
        └──┬───┘
           ↓ 事件完成
        ┌──────┐
        │ 终止 │
        └──────┘
```

### 进程 vs 线程

| 对比 | 进程 | 线程 |
|------|------|------|
| 调度单位 | 是 | 是（轻量级） |
| 资源 | 独立地址空间、文件描述符 | 共享进程地址空间 |
| 开销 | 创建/切换开销大 | 创建/切换开销小 |
| 通信 | IPC（管道、共享内存、消息队列） | 直接读写共享变量 |
| 崩溃影响 | 一个进程崩溃不影响其他 | 一个线程崩溃导致整个进程终止 |

### 线程实现方式

| 方式 | 说明 |
|------|------|
| 用户级线程 | 线程管理在用户空间，内核不可见。一个线程阻塞导致整个进程阻塞 |
| 内核级线程 | 线程管理在内核，一对一映射。OS 可调度线程，开销较大 |
| 组合模型 | 多个用户线程映射到少数内核线程（M:N 模型） |

## 进程通信

| 方式 | 说明 | 特点 |
|------|------|------|
| 共享内存 | 多个进程映射同一块物理内存 | 速度最快，需要同步机制 |
| 管道 | 半双工，一端写一端读 | 匿名管道用于父子进程 |
| 消息队列 | 内核中的消息链表 | 有格式的消息，异步 |
| 信号量 | 计数器，用于同步/互斥 | PV 操作 |
| 信号 | 异步通知机制 | 不可靠，信息量少 |
| Socket | 网络通信 | 可跨机器 |

## 处理机调度

### 三级调度

| 调度 | 位置 | 频率 | 说明 |
|------|------|------|------|
| 高级调度（作业调度） | 外存 → 内存 | 低 | 从后备队列选作业调入内存 |
| 中级调度（内存调度） | 内存 ↔ 外存 | 中 | 挂起/解挂，调整内存中的进程数 |
| 低级调度（进程调度） | 就绪队列 → CPU | 高 | 从就绪队列选进程分配 CPU |

### 调度算法

| 算法 | 特点 | 适用场景 |
|------|------|---------|
| FCFS（先来先服务） | 非抢占，简单 | 长作业 |
| SJF（短作业优先） | 平均等待时间最短，饥饿 | 批处理 |
| SRTN（最短剩余时间优先） | SJF 的抢占版本 | 抢占式 |
| 优先级调度 | 按优先级分配，可抢占/非抢占 | 通用 |
| 时间片轮转 RR | 时间片到就切换，公平 | 分时系统 |
| 多级反馈队列 | 多级队列 + 动态优先级 | 通用 |

::: tip 多级反馈队列

```text
队列 0 (最高优先级): 时间片小 → 新进程进入
  ↓ 时间片用完降级
队列 1: 时间片中等
  ↓ 时间片用完降级
队列 2 (最低优先级): 时间片大 → FCFS

特点: 短作业在高层队列快速完成，长作业逐渐降级，兼顾响应时间和吞吐量
```

:::

## 同步与互斥

### 临界区

```text
进入区 → 临界区（访问共享资源） → 退出区 → 剩余区

进入区: 检查并设置标志，确保互斥
临界区: 访问共享资源的代码
退出区: 清除标志，唤醒等待者
```

### 实现互斥的软件方法

**Peterson 算法**（两个进程）：

```text
// 进程 i (i = 0 或 1)
flag[i] = true;          // 我想进入
turn = j;                // 让对方先
while (flag[j] && turn == j);  // 等待
// 临界区
flag[i] = false;         // 退出
```

### 信号量与 PV 操作

```text
信号量 S: 一个整型变量 + 等待队列

P(S): S--，若 S < 0 则阻塞（申请资源）
V(S): S++，若 S ≤ 0 则唤醒一个进程（释放资源）
```

**经典应用**：

#### 生产者-消费者问题

```text
Semaphore mutex = 1;   // 互斥访问缓冲区
Semaphore empty = n;   // 空闲缓冲区数
Semaphore full = 0;    // 已占用缓冲区数

生产者:
P(empty)     // 有空位吗？
P(mutex)     // 独占缓冲区
  放入数据
V(mutex)
V(full)      // 产品 +1

消费者:
P(full)      // 有产品吗？
P(mutex)     // 独占缓冲区
  取出数据
V(mutex)
V(empty)     // 空位 +1
```

::: warning PV 操作顺序
P 操作顺序不能颠倒！若生产者先 P(mutex) 再 P(empty)，可能导致死锁：缓冲区满时生产者锁住了 mutex 但等 empty，消费者拿不到 mutex 也无法 V(empty)。
:::

#### 读者-写者问题

```text
Semaphore rw_mutex = 1;  // 读写互斥
Semaphore mutex = 1;      // 保护 count
int count = 0;            // 读者计数

写者:
P(rw_mutex)
  写入
V(rw_mutex)

读者:
P(mutex)
  count++;
  if (count == 1) P(rw_mutex);  // 第一个读者阻塞写者
V(mutex)

  读取

P(mutex)
  count--;
  if (count == 0) V(rw_mutex);  // 最后一个读者释放
V(mutex)
```

#### 哲学家进餐问题

5 个哲学家围坐，5 根筷子，每人需要两根。

```text
避免死锁的方法:
1. 最多允许 4 人同时进餐
2. 奇数号先拿左、偶数号先拿右（打破循环等待）
3. 只有两根筷子都可用时才拿
```

### 管程

管程是更高级的同步机制，将共享数据和操作封装在一起。

```text
管程特征:
- 一次只允许一个进程进入管程
- 内部的条件变量支持 wait/signal
- 简化了 PV 操作的使用
```

::: tip Java 中的管程
Java 的 `synchronized` 关键字和 `wait()/notify()` 就是管程的实现。每个对象内置一个管程（monitor）。
:::

## 死锁

### 死锁条件

四个条件必须**同时满足**才会死锁：

| 条件 | 说明 |
|------|------|
| 互斥 | 资源一次只能被一个进程使用 |
| 持有并等待 | 持有资源的同时等待其他资源 |
| 不可剥夺 | 已分配的资源不能被强制回收 |
| 循环等待 | 进程之间形成资源请求的环路 |

### 死锁处理

| 方法 | 策略 |
|------|------|
| 预防 | 破坏四个条件之一 |
| 避免 | 银行家算法，动态检测安全性 |
| 检测 | 资源分配图检测环路 |
| 解除 | 撤销进程、回退、剥夺资源 |

### 银行家算法

```text
核心数据:
- Available: 可用资源向量
- Max: 每个进程的最大需求矩阵
- Allocation: 已分配矩阵
- Need: 还需要矩阵 = Max - Allocation

安全性检查:
1. 找 Need ≤ Available 的进程
2. 假设它完成，回收 Allocation
3. 重复步骤 1，直到所有进程都能完成（安全）
   或找不到可满足的进程（不安全）
```

::: tip 银行家算法例题
已知 5 个进程 P0~P4，3 类资源 A(10) B(5) C(7)。当前 Allocation 和 Max 已知，判断是否安全并决定是否分配。

解题步骤：

1. 算 Need = Max - Allocation
2. 算 Available = 总资源 - ΣAllocation
3. 找 Need ≤ Available 的进程，加入安全序列
4. 回收该进程资源（Available += Allocation），重复步骤 3
5. 若所有进程都进入安全序列 → 安全；否则 → 不安全
:::
