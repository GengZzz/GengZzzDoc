# 查找

查找是从数据集合中找出满足条件的元素的过程。408 考试重点考查各类查找算法的 ASL（平均查找长度）计算。

## 基本概念

**查找长度**：在查找过程中需要比较的关键字次数。

**平均查找长度（ASL）**：所有查找过程中比较次数的平均值。

$$ASL = \sum_{i=1}^{n} P_i \times C_i$$

其中 Pᵢ 为查找第 i 个元素的概率，Cᵢ 为找到第 i 个元素需要的比较次数。

## 顺序查找

从头到尾逐个比较，适用于顺序表和链表。

```c
int SeqSearch(SSTable ST, ElemType key) {
    ST.elem[0] = key;  // 哨兵，避免每次判断越界
    int i = ST.length;
    while (ST.elem[i] != key) i--;
    return i;  // 0 表示查找失败
}
```

**ASL**：

- 成功：ASL = (n+1)/2
- 失败：ASL = n+1（有哨兵时）
- 时间复杂度：O(n)

::: tip 哨兵的作用
将关键字存在 `elem[0]`，查找时无需判断 `i >= 0`，简化了循环条件。这是顺序查找的常用优化。
:::

## 折半查找

要求数据**有序**且支持随机访问（顺序表）。每次将查找区间缩小一半。

```c
int BinarySearch(SSTable ST, ElemType key) {
    int low = 1, high = ST.length;
    while (low <= high) {
        int mid = (low + high) / 2;
        if (ST.elem[mid] == key) return mid;
        else if (ST.elem[mid] < key) low = mid + 1;
        else high = mid - 1;
    }
    return 0;  // 查找失败
}
```

**判定树**：折半查找的过程可以用一棵二叉判定树表示。

```text
有序表 [1,3,5,7,9,11,13] 的判定树:

              7          ← 第 1 次比较 (mid)
            /   \
          3      11      ← 第 2 次比较
         / \    /  \
        1   5  9    13   ← 第 3 次比较
```

**ASL**：

- 成功：ASL = log₂(n+1) - 1（判定树中各层比较数的加权平均）
- 失败：ASL ≈ log₂(n+1)
- 时间复杂度：O(log n)

::: warning 折半查找的条件
必须是**有序**的**顺序表**。链表不支持折半查找（因为无法随机访问）。
:::

## 分块查找

将数据分为若干块，块内无序、块间有序。先在索引表中确定所在块，再在块内顺序查找。

```text
索引表:                数据:
  块1: 最大值 25       [18, 12, 25 | 38, 31 | 50, 47, 62]
  块2: 最大值 38
  块3: 最大值 62

查找 31:
1. 在索引表中找到块2（25 < 31 ≤ 38）
2. 在块2中顺序查找，找到 31
```

**ASL**：

- 设分为 b 块，每块 s 个元素
- ASL = (b+1)/2 + (s+1)/2
- 最优分块：s = √n，此时 ASL = √n + 1

## B 树

B 树是一种多路平衡查找树，常用于数据库和文件系统的索引。

### 定义

一棵 m 阶 B 树满足：

1. 每个结点**至多**有 m 棵子树（m-1 个关键字）
2. 除根外，每个非叶结点**至少**有 ⌈m/2⌉ 棵子树（⌈m/2⌉-1 个关键字）
3. 根至少有 2 棵子树（除非根就是叶子）
4. 所有叶子在同一层
5. 有 k 棵子树的结点有 k-1 个关键字，且递增排列

```text
一棵 3 阶 B 树示例:

              [30]
             /    \
       [10,20]    [40,50]
       / | \      / | \
   [5] [15] [25] [35] [45] [55]
```

::: tip B 树的性质

- B 树的高度：h ≥ log_m(n+1)
- m 阶 B 树的每个结点中关键字有序，方便查找
- B 树的查找、插入、删除都需要保证结点的关键字数在合法范围内
:::

### B 树的插入

1. 查找插入位置，插入到叶子结点
2. 若结点关键字数超过 m-1，**分裂**：取中间关键字上移到父结点，左右两部分作为两个子结点
3. 分裂可能导致父结点也溢出，需要逐级向上分裂

### B 树的删除

1. 若删除的是非叶子结点中的关键字，用其中序前驱（或后继）替代，转化为删除叶子中的关键字
2. 若删除后结点关键字数低于 ⌈m/2⌉-1：
   - 兄弟够借：从兄弟借一个关键字
   - 兄弟不够借：与兄弟合并

## B+ 树

B+ 树是 B 树的变体，更适合数据库索引。

### 与 B 树的区别

| 对比维度 | B 树 | B+ 树 |
|---------|------|-------|
| 关键字与数据 | 关键字和数据在一起 | 非叶子只存索引，数据全在叶子 |
| 叶子链接 | 无 | 叶子结点用链表相连 |
| 查找范围 | 不方便 | 范围查找效率高 |
| m 阶结点 | m-1 个关键字 | m 个关键字 |

```text
B+ 树示例:

          [10 | 20 | 30]       ← 非叶子（索引）
         /   |    |    \
   [1,3,5] [10,15] [20,25] [30,35,40]  ← 叶子（数据）
      ←————————————————————————→
               链表相连
```

::: tip 为什么数据库用 B+ 树

1. 磁盘友好：非叶子结点只存索引，一个磁盘页能容纳更多索引项
2. 范围查询高效：叶子结点链表相连，顺序扫描即可
3. 查找稳定：任何查找都必须走到叶子
:::

## 散列表

散列表（Hash Table）通过散列函数直接计算元素的存储位置，理想情况下查找时间 O(1)。

### 散列函数

| 方法 | 公式 | 说明 |
|------|------|------|
| 直接定址法 | H(key) = key 或 a·key+b | 关键字分布均匀时适用 |
| 除留余数法 | H(key) = key % p | 最常用，p 取质数效果好 |
| 数字分析法 | 取关键字的若干位 | 关键字已知时适用 |
| 平方取中法 | 取 key² 的中间几位 | 适于关键字位数较大的情况 |

### 冲突处理

**开放定址法**：发生冲突时，在表中寻找下一个空位置。

```c
// 线性探测法
int Hash_Insert(HashTable HT, int key) {
    int addr = key % P;
    while (HT[addr] != NULL && HT[addr] != DELETED) {
        addr = (addr + 1) % TableSize;  // 线性探测
        if (addr == key % P) return -1;  // 表满
    }
    HT[addr] = key;
    return addr;
}
```

探测方式：

| 方法 | 探测序列 | 特点 |
|------|---------|------|
| 线性探测 | H, H+1, H+2, ... | 简单，但易产生堆积 |
| 二次探测 | H, H+1², H-1², H+2², ... | 减少堆积 |
| 双重散列 | H, H+H₂(key), H+2·H₂(key), ... | 最均匀 |

**链地址法（拉链法）**：每个地址建一个链表，冲突元素挂在链表上。

```text
散列函数 H(key) = key % 7

  0: → [14] → [28] → NULL
  1: → [15] → NULL
  2: → [23] → NULL
  3: → NULL
  4: → [11] → [25] → NULL
  5: → [12] → NULL
  6: → [20] → NULL
```

::: tip 链地址法 vs 开放定址法

| 对比 | 链地址法 | 开放定址法 |
|------|---------|-----------|
| 冲突处理 | 挂链表 | 找下一个空位 |
| 删除 | 容易 | 需标记删除 |
| 空间 | 需要额外指针 | 不需要 |
| 装填因子大时 | 性能下降平缓 | 性能急剧下降 |
| 实际应用 | 更广泛 | 特定场景 |
:::

### 查找效率分析

**装填因子** α = 表中元素数 / 表长

- 链地址法：ASL ≈ 1 + α/2
- 线性探测法：ASL ≈ (1 + 1/(1-α)) / 2
