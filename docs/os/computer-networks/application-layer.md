# 应用层

应用层是网络体系结构的最高层，直接为用户提供服务。408 考试重点考查 DNS、HTTP、电子邮件协议。

## 网络应用模型

### C/S 模型

客户端/服务器模型。

```text
客户端 → 请求 → 服务器
客户端 ← 响应 ← 服务器

特点:
- 服务器固定 IP，客户端主动发起
- 服务器被动等待
- 典型: Web、FTP、Email
```

### P2P 模型

对等网络，所有节点既是客户端又是服务器。

```text
节点 A ←→ 节点 B
  ↕         ↕
节点 C ←→ 节点 D

特点:
- 无中心服务器
- 节点可直接交换资源
- 可扩展性好，但管理困难
- 典型: BitTorrent、区块链
```

## DNS 域名系统

将域名解析为 IP 地址，使用 UDP（端口 53）。

### 域名结构

```text
从右到左: 根 → 顶级域 → 二级域 → 三级域 ...

        . （根）
       / \
     com  cn  org  net  edu ...
    /     \
  baidu   sina
  /   \
www  mail

完整域名: www.baidu.com.（末尾的 . 表示根）
```

### DNS 查询方式

```text
迭代查询（常用）:
客户端 → 本地 DNS 服务器 → 根 DNS
                          ↓ "去 .com 的 DNS 问"
                        .com DNS
                          ↓ "去 baidu.com 的 DNS 问"
                      baidu.com DNS → 返回 IP

递归查询:
客户端 → 本地 DNS → 根 DNS → .com DNS → baidu.com DNS
                                             ↓
客户端 ← 本地 DNS ←─── IP ←─────────────────┘
```

::: tip DNS 使用的传输层协议

- 查询/响应：UDP（53 端口），因为数据量小、速度快
- 区域传送：TCP（53 端口），因为数据量大、需要可靠传输
:::

### DNS 记录类型

| 类型 | 说明 |
|------|------|
| A | 域名 → IPv4 地址 |
| AAAA | 域名 → IPv6 地址 |
| CNAME | 域名别名 |
| MX | 邮件服务器 |
| NS | 域名服务器 |
| PTR | IP → 域名（反向解析） |

## FTP 文件传输协议

使用两个 TCP 连接：

```text
控制连接（端口 21）: 传输命令和响应，持久连接
数据连接（端口 20）: 传输文件数据，按需建立

主动模式: 服务器主动连接客户端的数据端口
被动模式: 服务器被动等待客户端连接
```

| 模式 | 服务器数据端口 | 连接方向 |
|------|--------------|---------|
| 主动模式 | 20 | 服务器 → 客户端 |
| 被动模式 | 随机高位端口 | 客户端 → 服务器 |

## 电子邮件

### 系统组成

```text
发件人 → 用户代理(UA) → 邮件服务器 → SMTP → 邮件服务器 → UA → 收件人
                               │                    │
                          发件服务器           收件服务器
```

### SMTP（简单邮件传输协议）

- 用于**发送**邮件
- 端口 25
- 基于 TCP，使用 C/S 模式
- 只能传输 7 位 ASCII 码（MIME 扩展支持多媒体）

### POP3（邮局协议）

- 用于**接收**邮件
- 端口 110
- 下载并删除模式 / 下载并保留模式
- 不支持在服务器上管理邮件

### IMAP（互联网邮件访问协议）

- 用于**接收**邮件
- 端口 143
- 支持在服务器上管理邮件（创建文件夹、搜索）
- 支持离线操作

| 对比 | POP3 | IMAP |
|------|------|------|
| 邮件存储 | 下载到本地 | 保留在线上 |
| 多设备同步 | 不支持 | 支持 |
| 服务器管理 | 不支持 | 支持 |

::: tip 发送 vs 接收

- 发送邮件：SMTP（发件人 → 发件服务器 → 收件服务器）
- 接收邮件：POP3/IMAP（收件服务器 → 收件人）
- 邮件服务器之间也用 SMTP 传递
:::

## WWW 与 HTTP

### URL 格式

```text
协议://主机名:端口/路径

例: https://www.example.com:443/path/page.html
    ├────┤   ├──────────┤├─┤ ├─────────────────┤
    协议    主机名       端口  路径
```

### HTTP 协议

超文本传输协议，基于 TCP（端口 80 / HTTPS 端口 443）。

#### HTTP 版本演进

| 版本 | 特点 |
|------|------|
| HTTP/1.0 | 每个请求建立新 TCP 连接 |
| HTTP/1.1 | 持久连接（Keep-Alive），管道化，同一 TCP 连接可发多个请求 |
| HTTP/2 | 多路复用、头部压缩、服务器推送 |
| HTTP/3 | 基于 QUIC（UDP），解决队头阻塞 |

#### HTTP 请求方法

| 方法 | 说明 |
|------|------|
| GET | 获取资源，参数在 URL 中 |
| POST | 提交数据，参数在请求体中 |
| PUT | 更新资源 |
| DELETE | 删除资源 |
| HEAD | 只获取响应头 |

#### HTTP 状态码

| 分类 | 说明 | 常见 |
|------|------|------|
| 1xx | 信息性 | 100 Continue |
| 2xx | 成功 | 200 OK, 201 Created |
| 3xx | 重定向 | 301 永久, 302 临时, 304 Not Modified |
| 4xx | 客户端错误 | 400 Bad Request, 403 Forbidden, 404 Not Found |
| 5xx | 服务器错误 | 500 Internal Error, 502 Bad Gateway, 503 Unavailable |

#### HTTP 报文格式

```text
请求报文:
GET /index.html HTTP/1.1        ← 请求行
Host: www.example.com           ← 首部行
Connection: keep-alive
Accept: text/html
                                ← 空行
                                ← 实体主体（POST 有）

响应报文:
HTTP/1.1 200 OK                 ← 状态行
Content-Type: text/html         ← 首部行
Content-Length: 1024
                                ← 空行
<html>...</html>                ← 实体主体
```

### HTTPS

HTTP + TLS/SSL，对传输内容加密。

```text
HTTPS 连接建立:
1. 客户端发送支持的加密算法列表
2. 服务器返回证书（含公钥）
3. 客户端验证证书，生成预主密钥
4. 用服务器公钥加密预主密钥发送
5. 双方用预主密钥生成会话密钥
6. 之后的通信用会话密钥对称加密
```

::: tip 非对称 + 对称加密
TLS 握手阶段用**非对称加密**（RSA/ECC）交换密钥，数据传输阶段用**对称加密**（AES）加密内容。原因是非对称加密慢，只用于安全交换密钥。
:::

## 高频考点总结

| 考点 | 频率 | 说明 |
|------|------|------|
| DNS 解析过程 | 极高 | 迭代 vs 递归查询 |
| HTTP 状态码 | 高 | 301/302/304/404 含义 |
| SMTP vs POP3 vs IMAP | 高 | 发送 vs 接收的区别 |
| HTTP 版本差异 | 中 | 1.0/1.1/2 的改进 |
| HTTPS 握手 | 中 | 非对称加密交换密钥 |
| FTP 双连接 | 中 | 控制连接 vs 数据连接 |
