# 传输层

传输层提供端到端的逻辑通信。408 考试重点考查 TCP 连接管理、流量控制、拥塞控制。

## 传输层功能

| 功能 | 说明 |
|------|------|
| 复用与分用 | 多个应用进程共用传输层服务（通过端口号区分） |
| 可靠传输 | TCP 提供确认、重传、排序（UDP 不提供） |
| 流量控制 | 控制发送方速率，匹配接收方处理能力 |
| 拥塞控制 | 防止过多数据注入网络导致全局拥塞 |

### 端口号

| 范围 | 类型 | 举例 |
|------|------|------|
| 0~1023 | 熟知端口 | HTTP=80, HTTPS=443, FTP=21, SMTP=25, DNS=53 |
| 1024~49151 | 注册端口 | MySQL=3306 |
| 49152~65535 | 动态端口 | 客户端临时分配 |

## UDP 协议

用户数据报协议，无连接、不可靠但高效。

### UDP 特点

- 无连接：不需要建立连接
- 不可靠：不保证交付、不排序、不重传
- 面向报文：保留应用层消息边界
- 支持一对一、一对多、多对多通信
- 无拥塞控制：适合实时应用

### UDP 首部格式

```text
 0            16            31
┌──────────────┬──────────────┐
│   源端口      │   目的端口   │
├──────────────┼──────────────┤
│   长度        │   校验和     │
├──────────────┴──────────────┤
│           数据               │
└─────────────────────────────┘

首部仅 8 字节
```

### UDP 校验

使用伪首部（包含源 IP、目的 IP、协议号）参与校验，确保数据送到正确的主机和端口。

## TCP 协议

传输控制协议，面向连接、可靠的传输层协议。

### TCP 特点

- 面向连接：通信前需三次握手建立连接
- 可靠传输：确认、重传、排序、去重
- 面向字节流：不保留消息边界
- 全双工：双向同时通信
- 点对点：只能一对一

### TCP 首部格式

```text
 0            16            31
┌──────────────┬──────────────┐
│   源端口      │   目的端口   │
├──────────────┴──────────────┤
│                    序号      │
├─────────────────────────────┤
│                  确认号      │
├──────┬──────┬───────┬───────┤
│数据偏│保留   │标志位  │窗口   │
│移(4) │(6)   │(6位)  │大小   │
├──────┴──────┴───────┴───────┤
│   校验和       │  紧急指针   │
├────────────────┴────────────┤
│        选项（可变长）         │
└─────────────────────────────┘
```

**标志位**：

| 标志 | 含义 |
|------|------|
| SYN | 同步序号，建立连接 |
| ACK | 确认号有效 |
| FIN | 发送方数据发送完毕 |
| RST | 重置连接 |
| PSH | 推送，接收方应尽快交付 |
| URG | 紧急指针有效 |

## TCP 连接管理

### 三次握手

```text
客户端                    服务端
  |                          |
  |──── SYN=1, seq=x ────→  |    第一次握手
  |                          |    (客户端 → SYN_SENT)
  |                          |    (服务端 → SYN_RCVD)
  |←── SYN=1, ACK=1, ────── |    第二次握手
  |     seq=y, ack=x+1      |
  |                          |
  |──── ACK=1, seq=x+1 ───→ |    第三次握手
  |     ack=y+1              |
  |                          |    双方进入 ESTABLISHED
```

::: tip 为什么需要三次握手？
防止已失效的连接请求到达服务端。如果只有两次握手，服务端收到旧的 SYN 就建立连接，浪费资源。第三次握手让客户端有机会拒绝旧连接。
:::

### 四次挥手

```text
客户端                    服务端
  |                          |
  |──── FIN=1, seq=u ─────→ |    第一次挥手（客户端 FIN_WAIT_1）
  |                          |
  |←── ACK=1, ack=u+1 ──── |    第二次挥手（客户端 FIN_WAIT_2）
  |                          |    （服务端 CLOSE_WAIT）
  |                          |    （服务端继续发送剩余数据）
  |                          |
  |←── FIN=1, seq=w ──────── |    第三次挥手（服务端 LAST_ACK）
  |                          |
  |──── ACK=1, ack=w+1 ───→ |    第四挥手（客户端 TIME_WAIT）
  |                          |    等待 2MSL 后关闭
  |                          |    （服务端 CLOSED）
```

::: tip TIME_WAIT 等待 2MSL

- 确保最后一个 ACK 到达服务端（若丢失，服务端会重传 FIN）
- 让本连接的所有报文在网络中消失，避免影响新连接
- MSL = 最大报文段生存时间（通常 2 分钟）
:::

## TCP 可靠传输

### 序号与确认

```text
发送方:
  发送序号 = 数据第一个字节的编号
  每发送一段数据，等待确认

接收方:
  确认号 = 期望收到的下一个字节编号
  确认号 = 已成功接收的最后一个字节 + 1
```

### 超时重传

```text
RTO = RTTs + 4 × RTTd     (加权平均 + 偏差)

RTTs = (1-α) × 旧RTTs + α × 新样本    (α = 1/8)
RTTd = (1-β) × 旧RTTd + β × |RTTs - 新样本|  (β = 1/4)
```

超时重传时间动态适应网络延迟的变化。

### 冗余 ACK（快重传）

```text
接收方每收到一个失序的报文段，就发送一个对已接收的最后一个有序字节的重复确认。

发送方连续收到 3 个重复 ACK → 立即重传（不等超时）
```

## TCP 流量控制

利用滑动窗口机制控制发送速率。

```text
接收窗口 rwnd: 接收方通告的可用缓冲区大小
发送窗口 = min(rwnd, cwnd)   (cwnd 为拥塞窗口)

           已发送    可发送      不可发送
         ┌────────┬─────────┬───────────┐
窗口:    │ 已确认  │ 未确认   │ 不允许发送 │
         └────────┴─────────┴───────────┘
                  └── rwnd ──┘
```

### 零窗口与持续计时器

```text
接收方 rwnd = 0 → 发送方停止发送
启动持续计时器 → 周期性发送零窗口探测报文
接收方缓冲区有空 → 回复非零窗口通告
```

::: tip 滑动窗口三要素

1. 窗口大小由接收方控制（流量控制）
2. 窗口可以动态调整
3. 窗口为 0 时发送方必须暂停
:::

## TCP 拥塞控制

拥塞控制防止过多数据注入网络，保护整个网络不被过载。

### 慢开始与拥塞避免

```text
ssthresh: 慢开始门限（初始值通常 65535）
cwnd: 拥塞窗口

慢开始阶段 (cwnd < ssthresh):
  cwnd 指数增长: 每个 RTT cwnd 翻倍
  1 → 2 → 4 → 8 → 16 → ...

拥塞避免阶段 (cwnd ≥ ssthresh):
  cwnd 线性增长: 每个 RTT cwnd + 1
  16 → 17 → 18 → 19 → ...

超时事件:
  ssthresh = cwnd / 2
  cwnd = 1
  重新进入慢开始
```

### 快重传与快恢复

```text
收到 3 个重复 ACK（不超时）:
  1. 快重传: 立即重传丢失的报文段
  2. 快恢复:
     ssthresh = cwnd / 2
     cwnd = ssthresh（新的门限值）
     直接进入拥塞避免（不从 1 开始）
```

::: tip 完整的拥塞控制流程图

```text
cwnd
  ↑
  │         超时 → ssthresh=cwnd/2, cwnd=1
  │        ╱
  │   ╱╱╱╱  拥塞避免（线性增长）
  │  ╱
  │ ╱  ← ssthresh
  │╱
  │ 慢开始（指数增长）
  │
  └────────────────→ 时间
```

:::

### 拥塞窗口变化示例

```text
初始: ssthresh=16, cwnd=1

cwnd: 1→2→4→8→16  (慢开始, 指数增长)
cwnd: 16→17→18→19→20→21→22→23→24  (拥塞避免, 线性增长)

超时! → ssthresh=12, cwnd=1
cwnd: 1→2→4→8→12  (慢开始)
cwnd: 12→13→14→15→16  (拥塞避免)

收到3个重复ACK → ssthresh=8, cwnd=8
cwnd: 8→9→10→11...  (拥塞避免, 不回1)
```

## 高频考点总结

| 考点 | 频率 | 说明 |
|------|------|------|
| TCP 三次握手/四次挥手 | 极高 | 过程、状态变迁、TIME_WAIT |
| TCP 拥塞控制 | 极高 | 慢开始/拥塞避免/快重传/快恢复 |
| TCP 滑动窗口与流量控制 | 极高 | rwnd 和 cwnd 的关系 |
| UDP vs TCP 对比 | 高 | 特点和适用场景 |
| TCP 序号与确认号 | 高 | 计算确认号 |
| 快重传 vs 超时重传 | 高 | 触发条件不同 |
