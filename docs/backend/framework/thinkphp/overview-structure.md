# 概览、目录与入口

ThinkPHP 的特点是上手快、约定清楚、中文资料多，适合后台系统、企业站、管理平台和中小型 API。它既可以做单应用，也可以做多应用项目。日常开发不要只关注“控制器能不能访问”，更要关注目录边界、配置加载、路由约束和模型查询是否可维护。

## 应用结构

常见目录：

| 目录 | 职责 |
| --- | --- |
| `app/controller` | 控制器，处理 HTTP 请求入口 |
| `app/model` | 模型，封装表映射、关联、查询范围 |
| `app/middleware` | 中间件，处理鉴权、限流、跨域、日志上下文 |
| `app/validate` | 验证器，封装输入校验规则 |
| `config` | 配置文件，如数据库、缓存、日志、队列 |
| `route` | 路由定义 |
| `public` | Web 入口目录 |
| `runtime` | 缓存、日志、临时文件 |

多应用模式下，会按模块拆分应用目录，例如 `app/admin`、`app/api`。不要把多应用当作简单文件夹分类，它更适合后台、开放 API、前台站点这些入口差异明显的场景。

## 入口文件

请求通常从 `public/index.php` 进入，由框架创建应用并处理请求。线上部署时 Web 根目录应该指向 `public`，不要把项目根目录暴露出去，否则配置、源码和运行文件有被访问的风险。

入口阶段主要完成：

1. 加载 Composer autoload。
2. 创建 App 实例。
3. 读取环境与配置。
4. 注册服务、路由、中间件。
5. 处理 Request 并发送 Response。

## 配置与环境

ThinkPHP 配置通常放在 `config/*.php`，环境差异放在 `.env`。日常建议：

- 数据库账号、缓存密码、第三方 token 放 `.env`，不要提交到仓库。
- 业务代码读取配置时使用 `config()`，不要到处直接读环境变量。
- 开发、测试、生产环境的 debug、日志级别、缓存驱动要明确区分。
- 生产环境关闭 debug，避免异常页泄露 SQL、路径和环境变量。

## 单应用还是多应用

选择标准：

| 模式 | 适合场景 | 注意点 |
| --- | --- | --- |
| 单应用 | API 或后台规模不大，入口一致 | 控制器目录要按业务分组，避免文件过多 |
| 多应用 | 后台、前台、开放 API 差异明显 | 公共服务要抽到 common 或 service，避免复制 |

多应用不是越多越好。拆应用后路由、中间件、配置和权限策略都会变复杂，只有入口和运行策略确实不同才值得拆。
